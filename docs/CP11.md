# CP11 — Quantity Assessment Fastpath

Base: merged CP10 main bff4b0bac5b9ecc4b760712af20f1f378a4ea2e6.
Branch: cp11-quantity-assessment-fastpath.

## Goal and invariants

- Minimize repeated CPU work in the packed/global quantity assessments.
- No changes to signals, threshold, enabled venues, Direct2 routes, ranking, source rotation,
  alternatives, V10 capacity, simulator, parameter values or provider policies.
- No change to possible/unknown/excluded semantics, seed repair, global proofs, probe
  domain or ascending probe order, fees, integer rounding, or overflow/unknown treatment.
- No additional filters, new prioritization, eviction or retained market-state cache.
- Existing CP10 production configuration is the live test reference.

## Implementation

1. Freeze full CP10 amounts.rs evaluator in amounts_reference.rs, compiled only for tests.
2. Reimplement rational product comparisons with an exact checked-u128 fast path;
   larger ordinary products use bounded stack-based 32-bit limbs, while unbounded
   product lengths fall back to the unchanged reference algorithm. Never use floating point.
3. Generate the same probe inputs using Vec + sort_unstable + dedup rather than
   inserting individually into a BTreeSet. Duplicate collapse and ascending order match.
4. Add bounded optional aggregate phase counters gated by GRAPH_SIGNALS_PROFILE:
   amount calls/time, minimum_input calls/time, quote calls/time, rational u128/stack/fallback.
5. Profile packed assessment, universe construction, global assessment and seed-repair
   separately in execution_candidates.preparation. Timings are nested; do not add
   overlapping numbers without checking their accounting.
6. Add deterministic differential cases for normal and edge integer liquidity levels,
   reserve curve, zero/unknown fees, variable level counts, both settlements, huge
   quantities and fixed seed repair. Only elapsed_ns is excluded from comparison.
7. Include an ignored frozen-workload microbenchmark for local controlled measurement,
   and 1200 deterministic rational-product stress comparisons against the old algorithm.
