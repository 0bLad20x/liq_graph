# CP10 — V10 Capacity & Direct2 Packing Fastpath

Base: merged CP9A–H main 1e676dafe098e61a33817be3927944bd4abb78c6.
Branch: cp10-v10-capacity-fastpath.

## Invariant contract

- Same venues: meteora_dlmm,pumpswap; same Direct2 and WSOL/USDC settlements.
- Preserve marginal signals, ranking, alternative order, diversity strategies,
  technical boundaries, amount assessment, queue behavior and V10 byte representation.
- No new filters, priority, deduplication, or signal trigger changes.
- Current Prepared manifests supply actual account blocks; DLMM bin arrays vary.
- No broadcasts, no wallet/RPC credential changes and no event history buffers.

## Implementation

1. Lazy decode fixed keys and precompute fixed flashloan vault PDAs.
2. Bound thread-local ATA cache to 4096 (wallet,mint,token_program) entries.
   Cache immutable derivations only, never mutable pool or bin-array data.
3. Hash-index merged account metadata, retaining first-seen order and
   writable/signer promotion; hash-index compiled account positions.
4. Incrementally insert a Direct2 alternative into the current request group
   and remove it on capacity rejection. Direct pools remain before partners;
   all other route kinds keep the original full installation.
5. Optional aggregate capacity phase profiling gated by GRAPH_SIGNALS_PROFILE.
   New execution_candidates.cp10_capacity_phases report: calls,
   instruction_ns, message_ns, instruction_failures, message_failures.
6. Preserve the original v1 message compiler for tests only; assert byte equality,
   account order, metrics and identical validation failures for both settlements,
   variable account widths (3, 6, 12, 24), Pump/non-Pump and 2-16 pools.
   Verify cached PDA derivation against the original cryptographic operation.
