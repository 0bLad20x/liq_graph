# CP12 — Exact Quote Fastpath (Direct2)

Base: merged CP11 main 66c3b058462572c57c4618b2a9057064a6452502.
Branch: cp12-exact-quote-fastpath.

## Scope and invariants

- Speed up the exact per-amount quoting hot path, **not** candidate discovery,
  ranking, source selection, prepared/admitted pools, V10 packing, or execution.
- Preserve **all** input amounts, quote outputs, complete estimates, optimistic
  global exclusion proofs, unknown/insufficient error reasons, fees, integer
  overflow behavior, sell/buy ordering, rounding and existing V10 request bytes.
- No reduced search/probe count, no float approximations, no thresholds or
  heuristics, no new RPCs or changes to enabled venues.
- No cross-observation, cross-revision, cross-worker or unbounded memoization.

## Technical implementation

The original CP11 evaluator is frozen as test-only
\`src/workers/execution_candidates/amounts_cp12_reference.rs\`.
Only the amount assessment's repeated \`estimate()\`/quote path uses
\`FrozenQuoteScratch\`; stand-alone \`quote()\` for evidence/calibration
still executes the original exact arithmetic path.

1. **Meteora DLMM / directed liquidity levels:** each
   \`(input slice index, direction, level, output component)\` stores an
   optional **exact** \`Result<u128, Issue>\` of the full-component input cost
   \`mul_div(capacity,rate_denominator,rate_numerator,true)\`. The first
   access calculates it; later amount probes reuse it. Partial-component
   output is still evaluated with the original exact \`mul_div\` for its
   actual left amount. Fee and overflow order is unchanged. Cache is only
   initialized after the original profile and direction validation.
2. **PumpSwap / reserve curve:** exact sum of the fixed three fee rates
   is cached only on the **buy** branch, on first use; individual
   \`ceil_fee\` calls remain independent. The sell quote uses the
   original reserve and fee path.
3. **Lifetime:** \`FrozenQuoteScratch\` is lazily instantiated on the *first actual*
   quote in a frozen \`amounts::assess()\` call and dropped on return. Proof-only
   assessment paths do not allocate a quote cache.
   It cannot share data across PoolPriceObservation revisions, packing
   strategies or globally.
4. **Performance evidence:** \`cp12_*\` counters in
   \`execution_candidates.cp11_quantity_phases\` (same report location)
   count level/reserve quotes, nanoseconds, repeated component-cost
   hits/misses, buy-fee hits/misses and wide/\`u128\` math paths.
   Counters are optional via \`GRAPH_SIGNALS_PROFILE\` and aggregate-only.
5. **Avoid speculative quote-result caching:** a separately indexed
   \`(pool,direction,amount)\` result map is deliberately not installed
   without measured duplicate-hit evidence. It could add overhead or
   uncontrolled memory growth, and is not needed for constant-level reuse.

## Verification

Run with exactly the same CP11 frozen fixtures and newly added deterministic
cached-quote traces, including multiple repeated and random quantities,
DLMM variable level counts, exhausted/partial coverage, reserve-curve
buy/sell fees, manifest mismatches, unknown transfer fees and integer
overflow cases.

- \`cargo build --locked --release\`
- \`cargo test --locked --release cp10_tests\`
- \`cargo test --locked --release cp11_\`
- \`cargo test --locked --release cp12_\`
- \`cargo test --locked --release cp12_frozen_quote_benchmark -- --ignored --nocapture\`
- \`cargo test --locked --release cp12_repeated_quote_benchmark -- --ignored --nocapture\`

Use both a low-quote assessment benchmark and a repeated-quote workload;
the latter exercises caching directly. Benchmarks are informational and do not
assert a minimum speedup. Benchmark and CI are not a substitute for the mainnet test.
