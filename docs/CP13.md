## Scope and boundaries

- Existing Raydium CPMM Discovery, Completion and V10 manifest remain authoritative; no new RPC worker, schema, routing rule or per-DEX signal engine.
- `src/workers/market_state/cpmm.rs` owns the protocol-specific rates, creator-fee-side policy, validation and layout tests.
- MarketState observes CPMM pool status/fee totals/mode, token0/1 vault reserves and **the actual on-chain AmmConfig**. Rates are not a hard-coded tier. Shared config accounts are deduplicated by account stream.
- Fee denominator 1,000,000. `trade_fee_rate` is on input. The independent, per-pool optional `creator_fee_rate` applies to input or output depending on `creator_fee_on`. Protocol/fund shares of trade fees are **not** added again.
- Accrued protocol, fund and creator fees in the vault are removed from the pricing reserves; balances changing across slots have existing `MixedSlotNonAtomic` provenance.
- Pool emits the existing shared `FeeValuation`, `DirectedLiquidity` and `PoolLiquidity` schema for both directions. Reserve snapshots provide order-of-magnitude *capacity*, not a trade-sizing proof or full quote.
- `amounts::profile` continues to allow the exact prior DLMM/Pump models only. A signal-only CPMM profile is **Unknown** to the exact amount evaluator; it is never silently interpreted as an empty DLMM window or used for a false negative quantity veto. The frozen pool/prognosis and V10 simulation trace retain comparison evidence.
- No source-level change to `graph_liquidity` or `graph_signals`. V10 keeps auto sizing and all its existing proof/capacity validations.
- Partial fee/price/manifest accounts never synthesize a net signal. Pool swaps disabled in the observed PoolState do not yield valid net rates.

## CP13 frozen CPMM calibration closeout (60-second run)

The first 600-second live run proved 979 admitted Prepared CPMM pools and 294 directed CPMM fee observations, but 72 completed CPMM V10 legs lacked a frozen output estimate (`amount_model_not_implemented`). This is an **observability gap only**, not a SignalEngine or V10 dispatch failure.

- `PoolLiquidity.cpmm_quote` freezes both effective token vault reserves, mint order, the real AmmConfig trade fee, creator fee enabled flag/effective rate, and the per-direction creator-fee charging side. The snapshot participates in the content digest.
- `market_state::cpmm::quote_base_input` calculates the exact Raydium base-input fee/constant-product integer rounding **at a caller-supplied amount**, without amount search and with no changes to candidate ranking/exclusion. Standard Token-2022 transfer-fee behavior remains `Unknown` rather than silently assumed zero.
- `Selection::calibration` now uses that frozen CPMM base-input quote for V10's observed gross input in both the per-leg and whole-cycle comparison. It logs the snapshot and explicitly identifies the quote basis; the actual V10 bank may differ from the sampled multi-account state.
- `scripts/cp13_calibration_check.py` reads **all** streamed compact execution events, counts CPMM completed V10 legs, missing quotes, and observed-versus-predicted output differences in bps. No invented profitability inference.
- Existing CP10–CP12 amount evaluation/proofs are unchanged. The signal-only CPMM profile intentionally remains `Unknown` to the pre-V10 exact amount evaluator.
