# CP20 – Snapshot Direct2 economic prediction (advisory)

Base: main 5670cb7977e807ed93e5f451286aa1d1a5a99746
Branch: cp20-direct2-economic-predictor

## Contract
- **No fixed trade size**: `ExecutionParameters.trade_size=0` is unchanged. The
  SolanaMevBot V10 executor independently chooses trade quantity.
- No trades are broadcast and no additional RPC is performed during ranking.
- Forecasts never exclude a route. Unknown token transfer behavior, incomplete
  execution windows, insufficient fee state and unsupported protocols remain Unknown.
- No new long-lived market cache. Predictions use frozen MarketState observations
  already included in candidate evidence.
- Signal graph remains Direct2 WSOL/USDC. Existing market-cap, TVL, 50 USD
  directional capacity gate and V10 transaction packing limits are unchanged.

## Mathematical contract
Given forward pool A and return pool B with frozen quotes:
`output(x)=quote_B(quote_A(x))`;
`dex_gain(x)=output(x)-x`;
`estimated_net(x)=dex_gain(x)-reference_network_cost`.
Cost includes the 5,000-lamport network-fee reference plus configured absolute
priority fee. USDC costs use the existing fixed 100 USD/SOL calibration.
This is NOT a live SOL/USD quote and does not include rent deposits,
unmodelled flashloan charges, Jito tips or bank-state changes.

Raydium CPMM: frozen reserves, trade and creator fees including creator-fee
direction. PumpSwap: virtual-adjusted quote reserves, physical quote limit,
and frozen LP/protocol/creator fee schedule. DLMM: traverse the current
Prepared bin execution window with each bin's raw price and output capacity;
freeze the current base+variable fee across those bins. Thus the DLMM forecast
intentionally differs from protocol-exact per-bin dynamic fee progression.
The predictor uses continuous f64 approximations and therefore never makes
negative exclusion proofs. Existing CP8C integer proof and V10 are unchanged.

The maximizer brackets the economically relevant range by doubling atomic
input quantity, locates window boundaries by feasibility bisection, uses a
golden-section maximum and checks neighboring representable integer amounts.
These are algorithmically derived evaluation points, not synthetic transaction
sizes or user-specified input grids. The result is a **forecast**, not an exact
global maximum guarantee for discrete fees, state changes or protocol transitions.

## Candidate priority and observability
- Fresh Direct2 source witnesses are sorted: modeled positive estimated net
  first (descending value), then Unknown (conservative), then modeled
  nonpositive. This only changes selection order when `CP9DMaxPairs` limits
  fresh candidates; it never changes the graph or removes any candidate.
- The explicit `Economic` alternative-packing mode prioritizes each optional pool against the opposite seed leg using forecast net gain; unresolved alternatives remain eligible. This is an approximation, not an exhaustive cross-alternative global search.
- For every dispatched pack, compare all valid directed direct/partner pool
  combinations included in the V10 request. Record the best modeled forecast
  (input, output, DEX gain, indicative net gain, pool addresses).
- `Selection.economic` and `Report.cp20_economic_*` expose coverage.
- The existing execution calibration includes `economic_prediction`
  and `economic_at_v10_input`: predicted output for the **actual pair and
  actual V10 input**. Only compare fully observed two-hop cycles.
- A same-slot observation is not proof of matching Solana bank state.
- The source ordering is still anchored in existing marginal-positive
  witnesses. A future checkpoint can broaden source discovery if measured
  coverage proves the source requirement restrictive.

## CP20R: full economic evidence and active candidate ranking

- The compact V10 execution journal is now **schema 6**. Every request
  records the full small economic forecast in `selection.economic`.
  Executed routes additionally record `calibration.economic_at_v10_input`.
  Both `snapshot_content_digest` and `snapshot_account_set_digest`
  are retained on each executed CPI leg. Full manifests and RPC responses
  remain bounded samples; per-request economic evidence is not sampled.
- Every submitted pack also records a SHA256 `packed_state_digest` over the
  directed pool membership, frozen liquidity content/account-set digests and
  fee parameters. This identifies repeated *observed* snapshots even when
  simulations have no complete DEX flow. Different Solana slots are reported
  separately. A repeated fingerprint is **not proof of an identical bank**
  and must never, by itself, suppress a live opportunity.
- Active candidate source prioritization uses the current consumer-owned
  MarketState observations (not old witness observations), preserving the
  existing marginal signal qualification. A rotating sample of up to 512
  is scanned and up to 96 valid candidates are economically scored per
  evaluation. Ranking is modeled positive profit descending, Unknown, then
  modeled nonpositive; no candidate is discarded on modeled nonprofit.
  Fresh candidates still take precedence over active ones.
- `scripts/execution_analyze.py` exports
  `cp20_economic_validation`: forecast/actual outcome groups, predicted
  optimal quantity compared to V10's chosen input **only for the same
  successful directed path**, output error at V10's input, counts of
  repeated packed frozen state and complete execution-path frozen state,
  plus distinct simulation-slot counts. Never mix WSOL/USDC raw amounts.
- Historical schema 4/5 journals remain readable. They cannot recreate
  the economic forecasts lost by the old compact column list; the
  re-analysis explicitly marks those fields absent instead of guessing.

## CP20S: state-aware V10 simulation scheduling

- Only the `Economic` packing mode activates this scheduler. Other packing
  strategies preserve their previous dispatch behavior.
- A bounded per-run record (up to 8,192 recent distinct source keys and
  8,192 packed keys) is owned by ExecutionCandidates. No persistent market
  history is added and no Worker-to-Worker RPC is introduced.
- Newly observed *directed source states* are considered ahead of recently
  dispatched source states, both among fresh signals and among the rotated
  active-candidate window. The exact packed request is checked again before
  existing CP8C quantity assessment; a state already submitted within the
  cooldown is skipped without changing proof/request delivery accounting.
- Default cooldown is 30 seconds, configurable with
  `GRAPH_CP20S_RECHECK_SECONDS` (0 disables; maximum 3,600).
  This is an operating interval, **not** a minimum trade size.
  Missing snapshot or fee evidence disables duplicate suppression for that
  candidate rather than fabricating a state identity.
- A repeated complete snapshot after the interval may be dispatched again.
  The cache records V10 *submission*, not successful execution. A short
  periodic recheck remains necessary because an unchanged snapshot digest
  is not proof of an unchanged bank or RPC outcome.
- Compact evidence journal schema 7 records `cp20s_schedule` per submitted
  request. Worker summary records counts deferred and counts of new/rechecked
  submissions. The offline analyzer separates outcomes by scheduling class.
- No changes to V10 `trade_size=0` or signing/execution pipeline.
